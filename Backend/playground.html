Welcome to the Huddle backend course

You’re building the backend for Huddle—the app that helps students find study spots on campus, rate them, and form study groups. This course walks you through the ideas and lets you try the API as you go.

Lesson 1: What is the backend for?

Huddle has a frontend (the app students see in the browser) and a backend (a server that talks to the database and does the heavy lifting).

  • The frontend might say: “Give me all study spots” or “Save this rating.”
  • The backend receives that request, talks to Firebase (our database), and sends back data—like a list of spots or “saved.”

We build endpoints (URLs like /api/spots or /profile). Each endpoint does one job. The frontend will call these when the app loads a map, when someone submits a rating, or when they view their profile.

Lesson 2: Requests and responses

Every time the app needs something from the backend, it sends a request. The backend runs the code for that URL and sends back a response (usually JSON).

  • Request: method (GET, POST, etc.) + path (e.g. /api/health) + optional body (for POST/PATCH).
  • Response: a status (200 = OK, 401 = not allowed, etc.) and data, e.g. {"ok": true} or {"spots": [...]}.

In the Activities you’ll send requests from this page and see the responses. That’s the same flow the real app will use.

Lesson 3: Methods and paths

GET = “give me data.” Examples: list of spots, one spot, health check, my profile.

POST = “here’s new data.” Examples: create a spot, add a rating, create a group.

PATCH = “update this.” Example: update my preferences.

DELETE = “remove this.”

The path says which resource: / = home, /api/health = health check, /profile = my profile (needs login). Some routes need an auth token so the backend knows who’s making the request.

Activity 3: Get my profile (protected route)

/profile returns “Hello user [your ID]” but only if the backend knows who you are. So the request must include an auth token (from Firebase when you’re signed in).

To get a token: sign in on the Huddle app, open DevTools → Network, trigger a request to the backend (e.g. “Fetch My Profile” on the dashboard), then copy the Authorization header value (the part after “Bearer ”). Paste it in the Auth token field below, click Get my profile, then Send.

Add token and click Send, or try without token to see 401.
