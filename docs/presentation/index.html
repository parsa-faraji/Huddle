Huddle

Find a study spot. Find your people.

A campus study-spot discovery, rating, and group-matching app for students.

The problem

Students don't know where to study.

Too quiet. Too loud.

Moffitt is packed at 8pm. The stacks are silent. Which floor has outlets? Who knows?

Nobody to study with.

You could DM 30 classmates on GroupMe and hope one is free. Or you could match with people already meeting for CS61A.

The solution

One app, three loops.

📍

Discover

List + map of campus spots with live crowd counts and community ratings.

✅

Check in

"I'm here now" for 15 min. Others see the live count — quiet floors stay honest.

💬

Huddle up

Join or create a study group for a course. In-app chat, iCal export, email blast.

Data flow

One subscription, zero REST

// src/context/AppContext.jsx
useEffect(() => {
  if (!user) return resetState();
  const unsubs = [
    subscribeSpots(setSpots),
    subscribeGroups(setGroups),
    subscribeUserDoc(user.uid, setUserDoc),
    subscribeUserSessions(user.uid, setSessions),
    subscribeActiveCheckins(setCheckins),
  ];
  return () => unsubs.forEach(u => u());
}, [user]);

Firestore onSnapshot listeners push updates in real time. No polling, no manual refresh. Unsubscribe on sign-out or unmount.

Part 3

Backend

Firebase · Node + Express · Vercel Functions

Storage

Firestore collections

  • users/{uid} — profile, prefs, joined spots/groups, favorites, theme
  • spots/{id} — metadata, lat/lng, ratingSum/ratingCount
  • groups/{id} — course, owner, member list, meeting info
  • groups/{id}/messages/{id} — in-group chat, 500-char cap
  • ratings/{id} — per-user per-spot rating, 9 axes
  • checkins/{id} — 15-min TTL presence, expiresAt Timestamp

Why Firestore?

  • Real-time onSnapshot subscriptions — crowd counts + chat are live with no extra infrastructure
  • Hosted auth integrates with the same SDK the frontend already uses
  • Security rules let us ship without a backend at all for most flows
Security

Rules, not trust

// firestore.rules
match /groups/{groupId} {
  allow read: if isSignedIn();
  allow update: if isSignedIn() && (
    (resource.data.ownerId == request.auth.uid)
    || request.resource.data.diff(resource.data)
         .affectedKeys().hasOnly(['memberIds', 'members'])
  );

  match /messages/{messageId} {
    function isMember() {
      return request.auth.uid in
        get(/databases/$(database)/documents/groups/$(groupId)).data.memberIds;
    }
    allow read: if isMember();
    allow create: if isMember()
      && request.resource.data.userId == request.auth.uid
      && request.resource.data.body.size() <= 500;
  }
}
Auth

Student gate

  • Signup only accepts academic suffixes — .edu, .ac.uk, .edu.au, .ac.jp, etc.
  • Password reset via Firebase Auth built-in email
  • Protected routes redirect unauthenticated users to /
  • Verified-student badge on Profile with school domain
// src/services/studentEmail.ts
const ACADEMIC = [
  '.edu', '.ac.uk', '.ac.jp', '.edu.au',
  '.edu.cn', '.ac.in', '.edu.sg', …
];
export function isStudentEmail(email) {
  const lower = email.toLowerCase();
  return ACADEMIC.some(suf => lower.endsWith(suf));
}

Crowd presence

// src/services/checkins.ts
export async function checkIn(uid, spotId) {
  await addDoc(collection(db, 'checkins'), {
    userId: uid,
    spotId,
    createdAt: serverTimestamp(),
    expiresAt: Timestamp.fromMillis(Date.now() + 15 * 60_000),
  });
}

export function subscribeActiveCheckins(cb) {
  const q = query(collection(db, 'checkins'),
    where('expiresAt', '>', Timestamp.now()));
  return onSnapshot(q, snap => cb(snap.docs.map(d => ({ id: d.id, ...d.data() }))));
}

Rules require each check-in to own its userId and include an expiresAt Timestamp. A one-minute client tick drops expired ones from the count even before Firestore pushes a new snapshot.
